# Reference corpus

Curated real-world panel screenshots fed to the draw model via cosine
retrieval. See `lib/references/` for the loader and `scripts/seed-reference.ts`
for the CLI.

## Files

- `index.json` — array of `Reference` rows. Generated by the seed CLI;
  do not edit by hand.
- `<id>.png` — sibling PNG for each entry. Filename comes from the
  `pngFile` field in the index row.

## Schema (per row)

```jsonc
{
  "id": "stripe-press-three-forces-2026-06-21",
  "pngFile": "stripe-press-three-forces-2026-06-21.png",
  "caption": "Three forces shaping the AI market",
  "genre": "tech-essay",
  "visualType": "structural",
  "whyItWorks": "Clean three-column grid. Single bronze accent on the middle column. Strong heading hierarchy — the headline is ~3× the body. Generous whitespace around the columns. Uses real vector text, not images of text.",
  "embedding": [0.123, -0.456, /* ...1536 numbers total... */]
}
```

The `embedding` is computed at seed time via OpenAI
`text-embedding-3-small` from a canonical query string of
`visualType + genre + caption` (see `referenceQueryText` in `lib/references/types.ts`).

## Adding a new reference

```bash
npx tsx scripts/seed-reference.ts \
  --png ~/Downloads/stripe-press-three-forces.png \
  --caption "Three forces shaping the AI market" \
  --genre tech-essay \
  --visualType structural \
  --why "Clean three-column grid, single bronze accent, strong heading hierarchy"
```

The CLI copies the PNG into `references/`, computes the embedding, and
appends a row to `index.json`. Re-run any time you find a panel worth
imitating.

## What makes a good reference

- **Real published work.** A screenshot from someone's actual
  LinkedIn / Pinterest / Twitter post or an editorial site. Not a
  Figma mock, not a stock template.
- **One panel per entry.** If a carousel has 6 great slides, that's 6
  entries — they retrieve independently.
- **Layout-shape variety.** Aim for breadth across `visualType` values
  (structural, flowchart, annotated_hero, etc.) before depth in any
  one. The corpus is more useful as a *vocabulary* of layouts than as
  a deep library in one style.
- **Specific `whyItWorks`.** "Clean and modern" is useless. "Single
  ink-on-cream colorway, sentence-case heading, tabular row alignment
  with 24px gutters" is gold. The model reads this verbatim.

## Capacity

The retriever scores the entire corpus per render. At ~200 entries
that's ~200 cosine ops on 1536-dim vectors — sub-millisecond. Past
~1000 we'd want an ANN index; not relevant in v1.
